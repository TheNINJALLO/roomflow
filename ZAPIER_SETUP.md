# RoomFlow Zapier email intake

RoomFlow accepts caller emails through the `intake-lead` Supabase Edge Function. Each successful delivery creates a shared customer and `New Lead` job that appears in both RoomFlow and Tracker.

## 1. Deploy the updated function

The repository code does not update the live Supabase function until `supabase/functions/intake-lead` is deployed to the RoomFlow Supabase project. Deploy it through your normal Supabase deployment workflow before testing the Zap.

## 2. Create the secure endpoint

In RoomFlow, open **Settings → Email Intake / Zapier**, create an endpoint, and immediately save the displayed POST URL and one-time webhook secret.

## 3. Configure Zapier

After the Gmail or Email Parser trigger, add **Webhooks by Zapier → POST**.

- URL: use the POST URL generated by RoomFlow.
- Payload Type: JSON.
- Header `x-roomflow-webhook-secret`: use the one-time secret.
- Do not place the webhook secret in an email body or ordinary caller field.

Recommended payload:

```json
{
  "source_message_id": "{{Gmail Message ID}}",
  "source_sender": "{{From Email}}",
  "source_subject": "{{Subject}}",
  "body_plain": "{{Body Plain}}"
}
```

Always map Gmail's stable Message ID. It lets RoomFlow recognize a Zapier retry and update the existing record instead of creating another job.

You can optionally map fields directly:

```json
{
  "source_message_id": "{{Gmail Message ID}}",
  "customer_name": "{{Caller Name}}",
  "phone": "{{Caller Phone}}",
  "email": "{{Caller Email}}",
  "address": "{{Service Address}}",
  "city": "{{City}}",
  "state": "{{State}}",
  "postal_code": "{{ZIP}}",
  "issue_description": "{{Reason for Call}}",
  "appointment_start": "{{Appointment Date and Time}}"
}
```

The endpoint also accepts form-encoded webhooks, nested Zapier records, raw email text, and HTML email bodies. Labels such as `Caller Name:`, `Call Back Number:`, `Service Address:`, and `Reason for Call:` are extracted automatically.

## 4. Verify the result

A successful Zapier test returns HTTP 200 or 201 with:

- `ok: true`
- `job_id` and `customer_id`
- `status` (`created`, `updated`, or `duplicate`)
- the `normalized` caller fields
- `warnings` for missing or unparseable optional data

Then verify the delivery in **RoomFlow Settings → Email Intake / Zapier → Recent deliveries** or the Zapier intake status strip above the Tracker job board. A rejected delivery is recorded there with its parsing error when the webhook credentials were valid.

If the response is 401, regenerate or recheck the endpoint URL and secret. If it is 422, inspect the returned normalized fields and make sure the Zap sends caller name, email, phone, or a labeled email body.
